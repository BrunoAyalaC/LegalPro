## Checklist

### 1. Backend Node

- **Bundle size**: Vite build analysis (`vite build --mode analyze`)
- **Latencia API**: medir p50/p95/p99 con APM (Sentry/OpenTelemetry)
- **N+1 queries**: detectar con profiler; usar eager loading (`json_agg`, JOIN)
- **Caching**: Redis con TTL apropiado, cache hit ratio > 70%
- **DB connections**: pool < 80%, query_timeout configurado
- **Compression**: gzip habilitado para respuestas > 1KB
- **Streaming**: para respuestas grandes (CSV, NDJSON)
- **HTTP caching**: ETag + `Cache-Control` + 304 responses

### 2. Backend .NET

- **Async all the way**: `async`/`await` sin `.Result` ni `.Wait()`
- **Compiled queries**: `EF.CompileAsyncQuery` para queries frecuentes
- **AsNoTracking**: para queries read-only
- **Response caching**: `[ResponseCache]` con VaryByQueryKeys
- **OpenTelemetry tracing**: auto-instrumentation ASP.NET Core + EF Core
- **Memory cache**: `IMemoryCache` + Redis distribuido

### 3. Frontend React 19

- **Bundle splitting**: `React.lazy` + `Suspense` por ruta
- **React 19 Compiler**: auto-memoization (sin `useMemo` manual en muchos casos)
- **Virtualization**: `@tanstack/react-virtual` para listas > 100 items
- **Image optimization**: AVIF/WebP con `srcSet`, `loading="lazy"`, `decoding="async"`
- **TailwindCSS 4**: solo utilities usadas (PurgeCSS automático)
- **Memoization**: `React.memo` para componentes puros
- **Code splitting**: por ruta, por componente pesado
- **No inline functions**: en props de listas grandes

### 4. PostgreSQL/Supabase

- **Índices compuestos**: multi-tenant + filtros frecuentes
- **Índices parciales**: `WHERE deleted_at IS NULL`
- **Índices GIN**: para búsqueda full-text (`tsvector`)
- **Índices BRIN**: para tablas append-only (audit_log)
- **EXPLAIN ANALYZE**: obligatorio antes de mergear queries pesados
- **VACUUM ANALYZE**: periódico después de inserciones masivas
- **Materialized views**: para reportes agregados

### 5. MiniMax

- **Selección de modelo**:
  - `MiniMax-M3` (default) — análisis complejo
  - `MiniMax-M2.5-highspeed` — chat rápido
  - `MiniMax-M3-large-context` — > 32K tokens
- **Cache de respuestas**: Redis con TTL
- **Prompt compression**: reducir tokens 30-50%
- **Function calling forzado**: `mode: ANY` para tareas críticas
- **Streaming**: SSE para UX en chat
- **Cost tracking**: `consumo_tokens_ia` tabla + alertas spike

### 6. Mobile Android

- **Lazy load de pantallas Compose**: `NavHost` + `composable`
- **Recyclerview**: para listas largas
- **Hilt**: DI eficiente
- **Coroutines + Flow**: para async
- **R8 + ProGuard**: release builds
