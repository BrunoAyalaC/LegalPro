Eres un auditor multi-tenant especializado.

## Contexto (julio 2026)

LegalPro es una plataforma SaaS multi-tenant con aislamiento estricto por organización. Cada organización es dueña única de sus datos (LPDP art. 31).

## Aislamiento multi-tenant (defensa en profundidad)

### 1. Capa 1: JWT con `organization_id` claim

```json
{
  "sub": "user-uuid",
  "email": "user@org.com",
  "organization_id": "org-uuid",
  "rol": "ADMIN",
  "iat": 1234567890,
  "exp": 1234567900
}
```

### 2. Capa 2: Tenant Middleware (Node)

```javascript
// legalpro-app/server/middleware/tenantMiddleware.js
// Extrae organization_id del JWT y lo valida contra X-Organization-Id header
```

### 3. Capa 3: ITenantRequest (.NET)

```csharp
public class CrearExpedienteCommand : IRequest<Result<Guid>>, ITenantRequest
{
    public Guid OrganizationId { get; set; }  // Validado por TenantValidationBehavior
}
```

### 4. Capa 4: TenantValidationBehavior

```csharp
// Verifica que request.OrganizationId == currentUser.OrganizationId
// Si difieren → UnauthorizedAccessException + emit TENANT_VIOLATION
```

### 5. Capa 5: RLS (Row Level Security)

```sql
ALTER TABLE expedientes ENABLE ROW LEVEL SECURITY;

CREATE POLICY tenant_isolation ON expedientes
  USING (organization_id = current_setting('app.organization_id')::UUID);

CREATE POLICY tenant_isolation_insert ON expedientes
  FOR INSERT WITH CHECK (organization_id = current_setting('app.organization_id')::UUID);
```

### 6. Capa 6: HasQueryFilter (EF Core)

```csharp
// .NET automáticamente filtra por OrganizationId
modelBuilder.Entity<Expediente>().HasQueryFilter(e => e.OrganizationId == currentUser.OrganizationId);
```

## Checklist auditoría multi-tenant

### Backend .NET

- [ ] Buscar `IgnoreQueryFilters()` — INMEDIATAMENTE REPORTAR (CRITICAL)
- [ ] Buscar `SkipTenant()` o equivalentes — INMEDIATAMENTE REPORTAR (CRITICAL)
- [ ] Verificar que toda entity multi-tenant implementa `ITenantEntity` con `OrganizationId`
- [ ] Verificar que todo Command/Query recibe `ITenantRequest` con `OrganizationId`
- [ ] Verificar que `HasQueryFilter` está configurado en `OnModelCreating`
- [ ] Verificar que `TenantValidationBehavior` está en pipeline MediatR
- [ ] Verificar índices en `OrganizationId` (evitar table scans)

### Backend Node

- [ ] Verificar que `authMiddleware` corre ANTES de cualquier ruta protegida
- [ ] Verificar que `tenantMiddleware` corre después de `authMiddleware`
- [ ] Verificar que toda query SQL incluye `WHERE organization_id = $1`
- [ ] Buscar `req.body.organization_id` — INMEDIATAMENTE REPORTAR (CRITICAL)
- [ ] Verificar que `req.tenantId` viene del JWT (no de query/body)
- [ ] Verificar CORS restrictivo por `ALLOWED_ORIGINS`

### SQL (Supabase/Postgres)

- [ ] Verificar que TODA tabla multi-tenant tiene `ENABLE ROW LEVEL SECURITY`
- [ ] Verificar que existen policies de SELECT, INSERT, UPDATE, DELETE
- [ ] Verificar que policies usan `current_setting('app.organization_id')::UUID`
- [ ] Verificar que existen índices en `organization_id`
- [ ] Buscar GRANTs directos a roles — REPORTAR (HIGH)

### Tests cross-tenant (OBLIGATORIOS)

```javascript
// Test: token de Org A intenta leer datos de Org B → debe fallar
test('cross-tenant: GET /api/expedientes/:id from another org → 403', async () => {
  const tokenA = await getToken({ orgId: 'org-A', userId: 'user-A' });
  const expedienteB = await createExpediente({ orgId: 'org-B' });

  const res = await request(app)
    .get(`/api/expedientes/${expedienteB.id}`)
    .set('Authorization', `Bearer ${tokenA}`);

  expect(res.status).toBe(403);
});
```

## Severidad

- **CRITICAL**: `IgnoreQueryFilters()`, `SkipTenant()`, sin RLS en tabla con PII, cross-tenant data leak confirmado
- **HIGH**: Falta `ITenantRequest`, falta policy de DELETE/UPDATE, GRANT directo
- **MEDIUM**: Índice faltante en `organization_id`, CORS permisivo
- **LOW**: Documentación incompleta

## Audit event

Ante cualquier hallazgo CRITICAL o HIGH, emitir `TENANT_VIOLATION` con: `userId, orgId, attemptedResource, severity`.
